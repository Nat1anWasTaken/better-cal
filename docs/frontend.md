# Frontend (web UI)

`frontend/` is the student workspace and the owner dashboard. It is a single-page app built with
Vite + React 19 + TypeScript (strict) + Tailwind CSS v4 + shadcn/ui (radix base, `radix-nova` style).
In production the Rust app serves `frontend/dist` from `STATIC_DIR`, with SPA fallback to `index.html`.
All API calls use relative `/api/v1/...` URLs.

## Scripts

| Command | What it does |
| --- | --- |
| `pnpm dev` | Vite on :5173. `/api` is proxied to `API_TARGET` (default `http://localhost:18080`). |
| `pnpm build` | Runs `tsc -b`, then `vite build` into `dist/`. It needs no running backend. |
| `pnpm gen:api` | Regenerates `src/api/schema.d.ts` from `../docs/openapi.json`. |
| `pnpm lint` | ESLint (typescript-eslint, react-hooks, jsx-a11y, @shadcn/lint and project design rules), with `--max-warnings=0`. |
| `pnpm test` | Vitest unit tests (`src/**/*.test.ts`). |
| `pnpm e2e` | Playwright against a live stack. `BASE_URL` sets the target (default the dev server). Credentials come from `E2E_STUDENT`/`E2E_STUDENT_PASSWORD` and `E2E_OWNER`/`E2E_OWNER_PASSWORD`. |

**API types.** `src/api/schema.d.ts` is generated by openapi-typescript and **committed**, so the
Docker build (`pnpm install --frozen-lockfile && pnpm build`) never reads the OpenAPI file or a backend.
After an API change, run `pnpm gen:api` and commit the result; `tsc` then reports any drift.
A few server fields are documented only as `Object` (card `span`/`raw`, catalog `RuleEntry`, preview cards).
Their exact shapes live in `src/api/types.ts`.

## Structure

```
src/

  lib/          pure helpers with unit tests: fillin (blank ranges), diff (visible whitespace),
                autosave (draft state machine), errors (JSON Pointer mapping), cards (grouping), format,
                preferences (defaults, Monaco theme/options mapping)
  hooks/        auth context, useDraft (autosave + localStorage backup + 409 conflicts),
                useSubmission (polling with backoff, 90 s give-up), useSite (30 s poll), useUnsavedGuard,
                usePreferences (saved editor preferences), useIsDark
  components/   CodeEditor (Monaco), EditorPreferencesFields / EditorPreferencesPopover, FeedbackCard / CardList, SubmissionResult, TestResults,
                Markdown (react-markdown + rehype-sanitize, raw HTML skipped), StatusPill, AppShell
  components/admin/  form helpers, PolicyEditor, PreviewPanel, StringList
  pages/        Login, Account (incl. forced password change), Preferences (/settings), Home, SetPage, ProblemPage,
                MySubmissions (+ detail), MyProgress, Playground (/playground), OAuthConsent (MCP clients' approval page)
  pages/admin/  Overview, Problems, ProblemEditor, Sets, SetEditor, ImportExport, Catalog, RuleEditor,
                CatalogTexts, CustomRule, RuleStats, Students, StudentDetail, Cohorts, ProgressMatrix,
                Submissions, Settings, Tokens (API 與 MCP: MCP server, connected apps, API tokens), Audit
e2e/            Playwright: auth setup (one login per role), student flow, fill-in, autosave/reload,
                active-set switch banner, teaching-text edit → preview → publish → restore, preferences + Vim,
                MCP OAuth consent → connection listed → disconnect (needs PUBLIC_URL on the stack)
```

The admin dashboard, the problem workspace and the history pages are lazy-loaded chunks, so the login
and set pages do not download Monaco.

## Design decisions

- **Visual direction.** Cool notebook-paper background, blue study ink as the primary colour, a violet
  "hint" accent used only on the hint ladder, Noto Sans TC for UI text and JetBrains Mono for code.
  Both fonts are self-hosted via @fontsource, because the CSP is `default-src 'self'`.
  Colours are semantic tokens defined in `src/index.css` (light and dark themes). Raw palette classes and
  hex values are lint errors.
- **Feedback cards are the core element.** Each card has the same sections in the same order:
  - 發生什麼事 / 可能原因（推測）/ 從哪裡看起 / 為什麼 / 下一步, a numbered hint ladder
    (「再給我一點提示（n/m）」), and the original compiler output collapsed.
  - Severity has an icon, a text label and a coloured spine.
  - Confidence uses a solid badge for "編譯器確認" and a dashed badge plus "系統判斷/推測" wording
    for guesses, so meaning never depends on colour.
  - The primary card is labelled 「建議先處理這一個」.
  - Knock-on errors and warnings sit in collapsed groups.
- **Workspace.**
  - On desktop: the statement on the left; the editor above the results on the right (both splits resizable), like the original cycu-cal.
  - Below 1024 px: tabs (題目 / 程式 / 結果). The editor tab stays mounted and the document survives layout switches.
  - Ctrl+Enter runs and Ctrl+Shift+Enter submits.
  - "Jump to location" scrolls to the reported line, highlights it and focuses the editor.
- **Editor preferences.**
  - Each user's editor theme, Vim mode, font size, tab width, word wrap, line numbers and minimap are
    stored on the server (`PUT /auth/preferences`, returned in `/auth/me`), so they follow students
    across lab machines. The site light/dark theme is still per browser.
  - Edited on `/settings` (偏好設定, from the account menu) with a live, editable preview, or from the
    gear button in the problem toolbar, which saves each change immediately.
  - `editor_theme: auto` follows the site theme by watching the `dark` class on `<html>`.
  - Vim mode uses `monaco-vim`, loaded on demand, with a mode line under the editor. It imports the old
    `monaco-editor/esm/vs/...` paths, which `vite.config.ts` aliases onto the same modules as
    `src/lib/monaco.ts`, so there is still one Monaco instance.
- **Fill-in problems.**
  - Template segments become editable ranges.
  - Edits outside the blanks are undone as soon as Monaco applies them, and the fixed text is dimmed.
  - The client sends only `{blanks}`. The server assembles the program from its own template, so this
    front-end restriction is a convenience, not the security boundary.
- **Autosave.**
  - A pure reducer drives the save states: clean / dirty / saving / offline / conflict.
  - Drafts save to the server after 1.5 s idle using `base_version`, and are mirrored to localStorage.
  - Offline saves retry every 10 s.
  - A 409 pauses autosave and asks "保留目前這份 / 載入另一份".
  - Run/Submit flush the draft first.
- **Judging status.**
  - The phases 等待中 → 編譯中 → 執行中 → 完成 come from the server `status`.
  - Status changes are announced via `aria-live`.
  - Polling backs off after 10 s and gives up at 90 s with an explicit "service, not your code" message.
    `retryable` submissions show 重新評測.
- **Active-set switch.** `GET /site` is polled every 30 s. When the active set changes while a problem is
  open, a non-blocking banner links to the new set and the editor content is untouched.
- **Forms.** Problem+json `errors[].pointer` are mapped onto fields, sometimes with a prefix such as
  `/content`. An unsaved-changes guard uses `useBlocker` (data router) plus `beforeunload`.

## shadcn lint (@shadcn/lint)

I read the official SETUP.md and README. `@shadcn/lint` 0.2.3 needs ESLint ≥ 9.30 and a TS parser.
This project uses ESLint 10 and typescript-eslint, so the two are compatible. The plugin is registered
in `eslint.config.js`, and discovery comes from `components.json` and the tokens in `src/index.css`.

| Rule | Setting | Notes |
| --- | --- | --- |
| `shadcn/no-raw-colors` | error | |
| `shadcn/no-arbitrary-values` | error | Recurring layout values became named `@utility` classes in `index.css`, e.g. `grid-cols-label`, `min-h-editor`. |
| `shadcn/no-inline-styles` | error | Dynamic widths go through CSS custom properties: `w-(--meter)`. |
| `shadcn/no-unknown-classes` | error | |
| `shadcn/require-static-classes` | error | |
| `shadcn/no-restyle` | error, `allow: ["layout"]` | Pages may place and size primitives; everything else goes through variants. |

`no-restyle` keeps primitives looking the same everywhere. Pages may only add **layout** classes
(width, margin, flex/grid placement, e.g. `w-44` on `SelectTrigger`, `ml-auto` on `Button`).
Typography, colour, shape and inner spacing belong to the component, so the recurring treatments are
named variants in `src/components/ui/`:

| Primitive | Variant | Used for |
| --- | --- | --- |
| `Button` | `ghost-destructive` | quiet delete / archive / revoke actions |
| `Input` | `code` | slugs, regexes, warning options |
| `Textarea` | `code`, `code-sm` | C source, test data, CSV, import JSON |
| `Label` | `option` | text beside a checkbox or switch |
| `DropdownMenuLabel` | `body`, `caption` | account name and section captions in menus |
| `SheetContent` | `sidebar` | the mobile admin navigation drawer |
| `Tabs` | `flush` | full-height tab layouts without the list/panel gap |

Unstyled Radix parts used as disclosure rows (`CollapsibleTrigger`, `CollapsibleContent`, a
`TabsContent` panel) are not restyled. The styling sits on a plain element instead: `asChild` with a
`<button>`, or a wrapper `<div>` inside the content, as the rule's messages suggest.

Project rule (`no-restricted-syntax`): raw Tailwind palette colours (e.g. `bg-red-500`) and hex
arbitrary colours (`text-[#…]`) are errors outside `src/components/ui/`.
`src/components/ui/` contains generated shadcn primitives, which are left as upstream ships them.

## Testing

- Unit (`pnpm test`, Vitest): diff rendering and visible whitespace; fill-in range building, extraction,
  edit permission and range mapping; the autosave state machine; problem+json pointer mapping; card
  grouping (primary / cascade / results / warnings); catalog template preview.
- E2E (`pnpm e2e`, Playwright, against the real API + judge-runner):
  1. A student runs code with a missing semicolon, sees the primary `syntax.missing_semicolon` card,
     reveals a hint, jumps to the line, opens the raw message, fixes the code and submits for 通過
     (including hidden tests).
  2. In a fill-in problem, typing in fixed code is rejected and a correct blank passes.
  3. A draft autosaves and is restored after reload.
  4. Switching the active set (via the owner API) shows the banner while the code is kept.
  5. An owner edits a rule title, previews it with the real compiler, publishes, then restores
     the built-in wording and publishes again.
  6. A student turns on Vim mode and a high-contrast theme on `/settings`; the problem editor uses them,
     Ctrl+Enter still runs, the choice survives a reload, and the toolbar popover turns Vim off again.
     Vim commands (`dd`, `x`, `A`) cannot change the fixed code of a fill-in problem.
